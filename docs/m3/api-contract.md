Checkpoint 1 catalogue editing, version conflicts, deactivation rules and reconciled item totals: [catalogue API contract](../workflow/catalogue-api-contract.md).
Technical Officer additions and unavailable stock-alert/TO-authoring policy: [operational API contract](../workflow/technical-officer-api-contract.md).
Security integration: GET /api/inventory/imports/{id} returns {id,committed,rowCount,rows} ONLY to stage owner with current TO role and all row-lab assignments; other callers/revoked scope get concealed404. No query params. Rows remain bounded100/immutable. GET locations now ADMIN or currently assigned TO only; assigned lecturer gets no location records (catalogue still available), no physical mutation granted. Item creation rejects ignored assetId as unsupported field. XLSX accepts only allowlisted UTF-8 standard single-sheet workbook parts/MIME types; VBA/OLE/externalLinks/comments/unexpected parts and alternate XML encodings are rejected.
Integration update: GET movements includes entries [{cell_id,account,delta,state,location_id,location_name,asset_id}] ordered by entry ID. External entries have null cell context. POST imports/preview validation failure422 returns {code:VALIDATION_FAILED,errors:[{row,column,code}],correlationId}; row numbers are spreadsheet numbers (header1,data2+), file-wide row0/column file, header errors row1. No stage on invalid rows. Scope errors use labId/DENIED without exposing references in unauthorized labs. Existing GET /api/admin/laboratories provides ADMIN {items:[{id,name}]}; non-admin TO uses scoped inventory locations with lab_id for selection. No new unrestricted lab lookup.

Base /api/inventory. Session cookie and X-CSRF-Token + Origin for writes; private no-store. All writes require UUID commandId (durable same-person/op identity; changed payload409). JSON closed schemas; quantities integer1..1000000, resulting balance<=1000000. Errors {code,correlationId}. No M4 custody/reservation APIs.

GET categories/items/locations/stock/assets/movements/adjustments/imports: query limit(default20,max100),offset(default0,max10000),q(max120),labId?,itemId?,categoryId?,kind?. Returns {items,limit,offset}. Catalogue categories/items available to every active role. Physical stock/location/assets/history scoped to assigned TO labs; ADMIN synthetic department read. No role-based operational bypass: stock writes require assigned TECHNICAL_OFFICER (ADMIN only with separate TO+lab assignment).

POST categories {commandId,name}; POST items {commandId,name,categoryId,kind:CONSUMABLE|RETURNABLE,uom}; POST locations {commandId,labId,name}: ADMIN.

POST receipts {commandId,itemId,labId,locationId,quantity,provenance}: assigned TO; initial anonymous stock, no serial required. Provenance unique within item/lab to reject duplicate physical receipt under new commandId.

POST assets {commandId,itemId,labId,locationId,expectedVersion,serial?}: materialize exactly one AVAILABLE anonymous unit, permanent UUID/internal code, no new receipt. Serial trimmed uppercase ASCII, internal spaces/punctuation preserved, unique per item. Optional serial only; conflicting serial rolls back conversion.

POST stock {commandId,itemId,labId,locationId,expectedVersion,fromState,toState,quantity,assetId?}: AVAILABLE/INSPECTION/MAINTENANCE only; no borrowed/reserved/transit/lost/retired/consumed transitions. Identified asset quantity1. Versions from stock cell; stale409. Paired immutable ledger/audit.

POST adjustments {commandId,itemId,labId,locationId,quantity,direction:ADD|REMOVE,reason,expectedVersion}: assigned TO proposes anonymous AVAILABLE correction; POST adjustments/{id}/approve {commandId}: separate current ADMIN, not proposer; original cell version checked, delta paired with adjustment account. Development independent-adjustment policy only, not academic approval.

POST imports/preview {commandId,format:CSV|XLSX,content}: CSV text or XLSX base64; max100 rows; columns itemId,labId,locationId,quantity,provenance ONLY. Server validates and stores immutable rows. Returns {id,rowCount,rows}. POST imports/{id}/commit {commandId}: owner/current scoped TO; all rows revalidated atomically, receipt provenance + stage row dedupe. Client preview is not trusted. XLSX parser capability will be reported explicitly if dependency unavailable.

Mutation results contain IDs/movementId/assetId/version as applicable. Reads use DB field names (snake_case); item kind uppercase. Scope applies before pagination/search. Pending adjustment/import details restricted. No edits/deletes of posted movements. This is an early interface; execution evidence follows implementation.
Final clarification: mutations return IDs, not a refreshed cell version; refresh stock after mutation for expectedVersion. assetId filter supported on movements for permanent-unit history. q search applies categories/items/locations/assets. item available counts expose only aggregate AVAILABLE; physical stock cells require scoped staff authority. All writes currently return200 from the inventory route.

XLSX implemented using pinned read-excel-file9.3.14, unzipper-esm0.13.3 and fflate0.8.3. JSON stream<=750000bytes, content<=700000characters, ZIP input<=512000bytes, <=32entries, <=1MB/entry and2MB total actual decompressed bytes, no path traversal/duplicates/DTD/entities/formulas, one worksheet<=101rows incl header/5columns, cell<=300characters. Normalized library ZIP reconstruction avoids hidden local-entry differences before workbook parsing. CSV same row/cell/header requirements; RFC-style quoted commas/newlines supported. Import admission current TO+CSRF and3/minute per-person; one parser per process. Preview rejects existing provenance and within-file duplicates; commit rechecks all rows and rolls back whole batch on concurrent conflicts. No uploaded statuses or direct asset/custody fields.
