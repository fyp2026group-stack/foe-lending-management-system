## Inventory and database contract detail

For every item and ownership lab: `opening + external receipts + net approved adjustments + received inbound ownership − received outbound ownership = available + reserved + borrowed + inspection + maintenance + source-owned transit + lost + retired + consumed`. Opening stock is either an opening balance or a receipt, never both. Lost/retired/consumed are historical accounting pools, excluded from lendable on-hand. External source/sink entries balance the chosen ledger boundary. Fix posting examples for corrections, write-offs and disposal before choosing whether any terminal pool is ever reduced; never count a write-off in both adjustment and lost stock.

Use a quantity partition on submitted revision: `submitted = issued cumulative + cancelled unissued + rejected quantity + remaining eligible/pending`. Active reserved is a subset of eligible unissued, not an additional requested quantity. Expired holds return to eligible unissued; re-reserving cannot increase submitted. For returnables `issued = physically received + loss resolved + outstanding`. Inspection disposition changes stock state after receipt, not cumulative return quantity. Immutable events plus transactional projections reconcile these dimensions.

Identity conversion posts one anonymous-unit debit and one identified-unit credit in the same pool; it is neither a receipt nor an adjustment. Asset item and current custody/location must agree with ledger and loan. Consumables require lot/state balances, no asset-per-unit, return custody or overdue. Block kind/UOM changes once used, with a future governed conversion instead.

Schema design must spell out not-null/XOR constraints, null-safe uniqueness, composite FKs, positive integer quantities, immutable history grants and deferred balancing checks. PostgreSQL row CHECK constraints cannot establish cross-table totals; use reviewed locking/procedures and reconciliation ([official constraints documentation](https://www.postgresql.org/docs/current/ddl-constraints.html), checked 2026-11-08). This supports Phase 1's approach rather than replacing it.

## Workflow reconciliation

| Command | Required current facts | Atomic outcome |
|---|---|---|
| Submit | Active borrower; valid revision/policy/eligible lecturer | Freeze snapshot; create ordered steps, or satisfy none policy; no loan |
| Decide | Current scoped capability; correct stage/revision; nonborrower; distinct stage actor if adopted | Append decision; advance stage; final approval may attempt allocation |
| Reserve | Academic approval; eligible remainder; current availability and authorized initiator | Allocate bounded quantity; no physical issue; shortage remains awaiting stock |
| Handover | Different current lab TO; active borrower; approved terms; live allocation; actual identity/assets | Consume hold, identify if needed, post custody/ledger/audit/event result together |
| Cancel/expire | Only unissued quantity; current actor/expiry guards | Release affected holds; preserve all issued custody/history |
| Receive | Current receiving authority; outstanding custody; actual physical receipt | Resolve received quantity into inspection/maintenance, never direct availability |
| Extend / clear / loss / recover | Explicit approved authority and independent actors where required | Append decision/event and update projection without rewriting historical facts |

Policy snapshots freeze academic rules, but current person capabilities are checked again. Revoking an approver stops new decisions; whether an already completed approval survives later assignment revocation must be decided separately from that actor's future authority. Recommend retain completed decision unless explicitly rescinded; rescission blocks unissued remainder and never silently reverses physical custody.
