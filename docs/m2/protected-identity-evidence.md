# Protected identity implementation and local evidence

Migrations005–007 applied to existing isolated PostgreSQL15 database; prior applied SQL files unchanged. Runtime has no table/sequence privileges in lab (including credentials, token hashes, verifier secret and audit). No role memberships; NOSUPERUSER/NOCREATEDB/NOCREATEROLE. Only login_start, login_finish, identity_call and denial functions executable. Functions have fixed trusted search_path, no dynamic arbitrary SQL, no PUBLIC execute. Nonlogin function owner has explicit underlying DML only, no table ownership; audit INSERT only. Deferred profile checker uses that nonlogin identity because deferred triggers execute after returning to runtime.

Login_start limits global/account attempts and returns only a one-use60second challenge plus hash for bounded server scrypt verification. Login_finish requires HMAC proof using secret unavailable to runtime SQL role, consumes challenge, checks current active user and unchanged credential hash, and generates session/CSRF/token server-side in DB. It cannot mint a session from a supplied user ID. Raw token is never persisted. No success audit actor/time arguments exist. Service compromise exposing verifier secret remains a privileged threat; this is not proof against compromised application process. Rate-limited login_start exposes credential hashes to the server/runtime caller by design: offline guessing of an obtained hash remains a residual; no broad credential-table read is granted.

LOGIN_VERIFIER_SECRET generated and appended to ignored .verification/m2.env; DB copy in private table. Provision via node --env-file=.verification/m2.env scripts/provision-verifier.mjs. App must reload configuration before new login. Never output this configuration. This setup command is deliberately restricted to dedicated lab_m2_test_identity. No new dependency/network access used.

identity_call validates opaque raw session token, disabled state, absolute8h/idle30m expiry and current ADMIN for synthetic single-department management. Writes validate CSRF, serialize exclusively against shared auth reads/login, update roles/labs/disabled and revoke target sessions atomically with before/after audit. Runtime cannot self-promote by providing actor IDs. Return objects preserve API DTO. Application origin checks remain application-layer. Invalid governance inside function rolls back its subtransaction then records fixed-code denial; malformed HTTP validation uses separate bounded denial interface. Denial actor resolves only current non-disabled/nonexpired/nonrevoked session, else null; callers cannot assert actor/time/success. Denial audit capped100/minute globally, so deliberate flood can cause audit gaps. Audit failure fails closed; no unauthorized execution.

Actual checks: protected-identity.test.mjs under runtime credentials denies base reads/DELETE on nine sensitive tables, audit INSERT, schema CREATE; rejects forged and consumed challenges; verifies admin/own reads, nonadmin denial, CSRF denial, successful batch/user writes, unknown field rejection, role replacement/disable revocation, self-change denial, logout and post-logout denial. Owner-only oracle verifies before/after roles/disable audit and anonymous attribution for disabled-session denial. Migration repeat succeeds. No HTTP/browser or full concurrent revocation proof claimed; independent Security review pending.

Supersedes direct-DML exception in earlier backend ADR/evidence. SEC02 implemented boundary awaits independent assessment, not declared closed. Remaining institutional MFA/SSO/scopes, production deployment, credential recovery, address abuse control and SQL/HTTP adversarial/concurrency coverage remain outside acceptance evidence.
