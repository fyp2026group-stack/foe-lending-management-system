# Assumptions, policy questions and proposed defaults

All defaults below are proposals for architecture review, not university policy. Approval of these documents must explicitly accept or amend the high-impact choices. Block affected implementation until resolved; unrelated work may proceed only after Phase 2 authorization.

| ID  | Open decision                                                    | Recommended default                                                                          | Consequence / alternative                                                                      |
| --- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| P01 | Who approves staff/HOD borrowing when ordinary approver is self? | Independently assigned eligible substitute; block if unavailable                             | Never auto-approve; institution must designate legitimate substitute authority.                |
| P02 | HOD/Admin equivalence and role holders                           | One administrative role, explicit approval capability grants                                 | Separate IT admin from academic HOD if needed; not every user admin becomes academic approver. |
| P03 | Both approvals ordering                                          | Lecturer then HOD, per line                                                                  | Parallel is possible but changes review context; fix before M4.                                |
| P04 | Partial outcomes                                                 | Independent line approvals/reservations and partial handover                                 | Reject-whole-request alternative simpler but less flexible.                                    |
| P05 | Stock reservation timing                                         | Reserve after final academic approval; none-policy lines ready immediately                   | No guarantee on submission; stock shortage remains approved-awaiting-stock.                    |
| P06 | Reservation expiry                                               | 48 hours from reservation; expire safely on read/action until an authorized scheduler exists | No automation created; configurable university collection windows may replace duration.        |
| P07 | Loan term/limits                                                 | Due date explicitly approved; configurable maximum and borrower limits                       | Do not invent number of days or quantities. Block issue with missing valid due date.           |
| P08 | Overdue restrictions/fines                                       | Show overdue; no automatic monetary penalties                                                | Lending ban or fines require institution decision.                                             |
| P09 | Lecturer eligibility                                             | Active explicit lab assignment and student selected eligible lecturer                        | Department/batch supervision relations can refine eligibility.                                 |
| P10 | TO coverage and sole officer borrowing                           | Different authorized TO in same lab; block self-handover                                     | HOD is not silently allowed to act as TO; approved substitute assignment needed.               |
| P11 | Serial uniqueness                                                | Normalized serial unique within manufacturer where manufacturer known                        | Manufacturer-less collision requires review; serial is not global identity.                    |
| P12 | Returnable anonymous stock                                       | Materialize asset identity by handover even without serial                                   | Permanent internal ID required for returnables; consumables remain quantity lots.              |
| P13 | Comments correction authorship                                   | Only original author appends correction; others reply separately                             | Privileged redaction needs separate governed process and retained audit.                       |
| P14 | Privacy/retention                                                | Keep required lending/audit evidence, policy-defined anonymization later                     | Legal owner must set student-data, audit and backup retention and erasure rules.               |
| P15 | SSO/MFA/account provisioning                                     | OIDC first if institution supports it; no self-service role elevation; privileged MFA        | Local login fallback needs separately reviewed recovery/password policy.                       |
| P16 | Adjustments and losses                                           | TO proposes, different inventory controller/HOD approves                                     | No silent write-off; institution decides thresholds and who can independently approve.         |
| P17 | Deployment/recovery                                              | University-managed Docker/PostgreSQL with encrypted off-host backups                         | Hosting, budget, domains, mail, TLS, recovery targets require authorization.                   |
| P18 | Reports and comments scopes                                      | Lab staff see assigned-lab operations, lecturers see assigned approvals, borrowers see own   | Batch membership alone never grants peer records. Admin access is logged.                      |
| P19 | Import/export size and file types                                | CSV/XLSX import, staged preview and explicit commit; bounded files/rows                      | No arbitrary URLs/files, macros or background jobs before review.                              |
| P20 | Damage and loss resolution                                       | Return physically received into inspection; no availability until cleared                    | Liability/payment policy outside scope; never mark replacement payment as physical return.     |
| P21 | Reservation fairness/future bookings                             | Current-stock holds, first successful atomic allocation                                      | Future overlapping time-slot booking and queue priority are not included without approval.     |

Assumptions: one department; multiple labs; one authoritative PostgreSQL database; online-only transactions; students have one current batch but batch history persists; no data migration source supplied. Institution must identify approval substitutes, SSO owner, privacy owner and production operator. These are review decisions, not a request to disclose credentials or student data.
