# Checkpoint 1 catalogue API

Base `/api/inventory`. Existing POST/GET payloads remain compatible. Responses are private/no-store. Mutations require session cookie, same Origin, JSON and X-CSRF-Token; catalogue writes require current ADMIN. Runtime has no table access or helper execution.

`PATCH /categories/{id}`, `/items/{id}`, `/locations/{id}` require UUID `commandId` and integer `expectedVersion` >= 0. Bodies are closed schemas. Path ID cannot be overridden in JSON. Success `{id,version,active}` increments version once; exact command replay returns the original result after current authorization checks. Changed command payload gives 409 `IDENTITY_CONFLICT`. Stale version gives 409 `STALE_VERSION`; missing record gives 404 `NOT_FOUND`; unsafe references/stock give 409 `STATE_CONFLICT`; invalid values give 422. Errors include `correlationId` through HTTP.

Optional category/location fields: `name` (trimmed 1–120 characters), `active` (boolean). Location lab is immutable. Optional item fields: `name`, `categoryId`, `kind` (`CONSUMABLE` or `RETURNABLE`), `uom` (trimmed 1–40 characters), `active`, `specifications`. Specifications are a flat object of at most 30 string values, keys 1–80 characters, values <=500 characters, serialized size <=12000 bytes. POST items also accepts specifications. New records start active/version 0; POST responses include both fields.

Category deactivation requires no active items. Item/location deactivation requires no positive operational stock (terminal consumed/retired/lost history may remain) and no lecturer/HOD/approved lending lines. An active item requires an active category. Kind/UOM changes are rejected after any movement or lending reference. Inactive records cannot receive stock or new lending requests, including imports and replay with a new command. Catalogue and lending writes acquire a common inventory gate before stock row locks. Posted movements, entries and receipts remain immutable. Audit updates retain complete before/after catalogue values.

GET categories/items/locations add `active` and `version`; items also add `specifications`, `reserved`, `borrowed`, `currently_borrowed` (alias), `inspection`, `maintenance`, `consumed` and retain `available`. Totals sum current stock cells, including anonymous and identified units once each; no asset or location detail is added. `consumed` is the terminal stock balance, not a second sum of loan records. TO totals include assigned labs only; ADMIN totals retain department-wide access; other active roles retain aggregate catalogue visibility. `labId` narrows totals and never expands TO scope. Existing physical detail scope is unchanged.

Catalogue reads support `active=true|false` and `sort=id|name` (ascending, ID tie-break); item `categoryId`, `kind`, `itemId` and existing bounded `q`, `limit`, `offset`, `labId` remain supported. Unknown query fields, duplicate URL keys, unsupported sort/kind/active values are rejected. No `active` filter returns both active and inactive records for compatibility.

Evidence: `tests/catalogue.integration.mjs` runs under runtime role with rollback fixtures. HTTP/browser verification is separate.
